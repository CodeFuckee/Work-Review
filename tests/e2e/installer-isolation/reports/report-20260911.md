# E2E 测试报告（安装器隔离：Yue-Review vs Work-Review，2026-09-11）

- 运行环境：Windows（本机 HC-202608171632）、PowerShell 5.1、
  `tests/e2e/installer-isolation/run.ps1 -InstallerPath <安装包>`
- 被测安装包：
  - RED 复现：`Yue-Review_1.1.32_x64-setup.exe`（线上 v1.1.32，含 bug：mainBinaryName=Work_Review）
  - GREEN 验证：本地构建 `Yue-Review_1.1.31_x64-setup.exe`（修复后：mainBinaryName=Yue_Review，本地版本号停留 1.1.31 不影响验证）
- 旧版载体：本机已安装的 Work-Review（`Work_Review.exe`，数据目录 `%APPDATA%\work-review`）

## RED 轮失败分析（产品缺陷复现，全部同源）

| 用例 | 失败现象 | 归因 | 证据 |
|---|---|---|---|
| E2E-001 | 静默安装后旧 Work_Review.exe 进程（PID 29880）被杀 | **产品缺陷**：NSIS 安装器按 `mainBinaryName`（Work_Review.exe）查杀同名进程，误杀旧版 | reports/installer-isolation-*.json，"旧进程死亡: [29880]，存活: []" |
| E2E-002 | 期望的 `Yue_Review.exe` 不存在（旧包二进制仍叫 Work_Review.exe） | **产品缺陷**（同源）：二进制名未独立 | 同上 |
| E2E-003 | 新装 exe 不存在，无法启动并存验证 | 同上 | 同上 |
| E2E-004 | 旧进程已在 E2E-001 被杀，无法断言存活 | 同上 | 同上 |

## 覆盖评估

- 已覆盖：确认用例表 E2E-001~004 全部实现并执行；契约测试 C-001（标识符/二进制名/数据目录与旧版零交集）、C-002（CI 便携脚本/自识别新名 + 旧名兼容）进入 `appIndependence.test.ts`，随 `node --test` 常跑。
- 未覆盖（按计划排除）：macOS/Linux 安装器；v1.1.31 以前历史安装包；安装向导交互 UI 细节（由确认门 2 人工观察补充）。

## 稳定性评估

- GREEN 轮单次全过；无随机等待依赖（全部条件等待 + 安装器退出等待，超时 5 分钟兜底）。
- 脚本自身经历 3 处缺陷修复（PS 5.1 BOM/编码、$Args 自动变量冲突、$PSScriptRoot 参数默认值），已消除。
- RED 轮会真实杀掉机器上运行中的旧版 Work-Review（这正是被复现的缺陷），脚本清理阶段会自动重启它。

## 结论

测试正确复现了「安装 Yue复盘 时杀掉运行中的 Work-Review」缺陷（RED 0/4），修复（mainBinaryName=Yue_Review 及联动）后 4/4 通过；独立性契约测试入库存档。待用户有头确认（确认门 2）后随正常流程推送。
